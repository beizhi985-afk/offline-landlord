# 阶段1：多游戏入口与工程边界

## 目标

在V3.7稳定斗地主基线之上增加轻量应用壳，让用户先选择游戏，再进入对应入口。

阶段1只建立入口和边界，不开发第二款游戏的牌组、规则、机器人、房间或网络能力。

## 用户流程

```text
启动“离线牌局”
├─ 斗地主 → 原V3.7斗地主流程
└─ UNO → “开发中”占位页 → 返回游戏选择
```

## 新增边界

- `shared/GameType.kt`：保存可被应用壳和协议共同依赖的 `GameType`；`app/navigation` 保存应用路由和轻量导航状态。
- `app/gameselection`：游戏选择界面和UNO占位界面。
- `OfflineGamesApp`：应用壳，根据当前路由组合选择页或原斗地主入口。

斗地主的 `GameEngine`、机器人、牌桌、手牌交互和网络代码保持原目录，不在阶段1进行物理迁移。

## 斗地主复用方式

- 点击“斗地主”后直接组合原有 `OfflineLandlordApp`。
- 原首页、创建房间、加入房间、附近发现、房间码、准备、机器人、叫地主、加倍、出牌、托管、断线恢复、重连和结算流程保持不变。
- “游戏选择”按钮只出现在尚未创建或加入房间的斗地主首页，牌局和房间中不新增返回入口。

## ViewModel与网络生命周期

- 阶段1之前，`GameViewModel`在 `MainActivity` 组合内容时立即创建。
- 阶段1之后，`GameViewModel`只在用户进入斗地主路由后创建。
- `GameViewModel`的构造本身不会启动网络；房主TCP服务和UDP广播仍只在创建房间时启动，客户端只在加入房间时连接，UDP发现仍只在用户点击发现时运行。
- 没有修改 `LanGameClient`、`LanGameServer`、`HostGameSession`、`LanDiscovery`或协议消息结构。

- 斗地主计分：未改变

## UNO范围

当前UNO只有可点击入口和“开发中”占位页。占位页仅展示未来方向：

- 单机机器人
- 2～4人局域网联机

阶段1没有UNO卡牌模型、规则引擎、机器人、协议、房间或网络操作。
